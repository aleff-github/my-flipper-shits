# CivSwitch → Flipper Zero: BadUSB research port (EXPERIMENTAL)

> **Status: static converter + automated build; no verified Flipper Zero or Nintendo Switch/2 execution.**
> This is **not** a tested jailbreak. It is deliberately excluded from the main payload index until hardware evidence exists.

Tracking: [aleff-github/my-flipper-shits#31](https://github.com/aleff-github/my-flipper-shits/issues/31). Original project: [Gezine/CivSwitch](https://github.com/Gezine/CivSwitch) (MIT); source revision pinned to `45649ae585c7df27a99ba378822ff5b1c124539c` (2026-11-05).

## Finding: why an ordinary DuckyScript port cannot be fully automatic

CivSwitch's [PicoSwitch firmware](https://github.com/Gezine/CivSwitch/tree/main/PicoSwitch) is a **composite USB HID device**:

1. A USB keyboard types the payload through Civilization VII's chat.
2. A Switch-compatible **gamepad** sends controller **A** button presses between lines and during the preamble.

Flipper's standard BadUSB `.txt` player implements keyboard input and `WAIT_FOR_BUTTON_PRESS` prompts, but **keyboard `A` is not controller `A`**. The provided converter retains the original ASCII chat strings and per-line command order while asking an operator to press `A` on a physical controller and resume Flipper. This is a **manual-assisted** transport, and requires *2N + 4* controller presses (including the initial five) and *2N* Flipper resume events for *N* payload messages. The result is impractically tedious for regular use, but is a source-compatible research baseline.

**Unknowns:** whether Switch 2 enumerates the Flipper's keyboard-only USB HID; the exact in-game focus handling; whether all punctuation is typed correctly; USB timings; game/firmware compatibility; whether the XSS and JavaScript bootstrap execute. No console or Flipper hardware tests were conducted.

## Quick start (computer with Git, Node.js/npm and Python 3.10+)

From this directory:

```bash
python -m unittest discover -v
python build_from_upstream.py --output generated
```

The builder clones `https://github.com/Gezine/CivSwitch.git`, checks out **exactly** the pinned SHA, runs `node --check core.js`, installs upstream's Terser dependency with `npm install --ignore-scripts --no-audit --no-fund`, executes upstream `node PicoSwitch/compress.js` to produce `payload.txt`, and then runs our validated Flipper converter. It **does not execute the payload itself**. The upstream source version is fixed; because its Terser dependency is a semver range rather than a committed lockfile, the generated bytes could still vary in future builds (the SHA-256 manifest records actual output).

Generated output:

- `generated/UPSTREAM_MIT_LICENSE.txt` — original Gezine MIT license, retained for attribution
- `generated/upstream_payload.txt` — original compressed chat payload, for comparisons
- `generated/CivSwitch_Flipper_Experimental.txt` — manually assisted BadUSB script
- `generated/build_manifest.json` — upstream commit, SHA-256 checksums, message counts, preservation check and explicit unsupported functionality

GitHub Actions attempts to build the same source-pinned payload in CI and attaches these files as an **experimental** workflow artifact. CI passing is **not** evidence that the exploit works on Nintendo hardware. The upstream Git revision is pinned, but third-party npm dependency versions are not locked, so this does not guarantee byte-for-byte reproducible builds.

**Existing checkout:** `python build_from_upstream.py --source /path/to/CivSwitch --output generated` (the checkout **must** be at the pinned revision).

**From an already-generated payload:** `python convert_payload.py /path/to/CivSwitch/PicoSwitch/payload.txt ./CivSwitch_Flipper_Experimental.txt`.

## Hardware validation (not yet performed)

1. On a computer you own, open a **blank text editor** (not a shell), select the US keyboard layout on the computer and Flipper, and run `keyboard_smoke_test.txt`. Compare the text precisely, including backticks, quotes, braces, pipes and punctuation. Do **not** run the full exploit against a computer terminal.
2. On the Flipper verify the longer generated file loads, stops at the intended prompts, and resumes in the proper sequence. This checks the script interpreter, not Switch compatibility.
3. A volunteer with a compatible console and the **physical Civilization VII 1.0.0 cartridge** must verify USB enumeration, in-game focus, text integrity, manual gamepad operation, full XSS execution, and post-exploit state. Testing requires explicit permission and acceptance of savedata/console risk. Do not mark the port `Working` based on a file generation or on a successful USB connection alone.
4. A production-quality *automatic* port would need a custom **composite keyboard+Switch-gamepad HID interface** on Flipper (custom firmware/app), or an externally attached gamepad device. Standard BadUSB does not implement this.
